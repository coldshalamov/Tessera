# Shared end-to-end acceptance scenario

Use invented, permission-cleared material: **The Lantern Room**, a 6–10 minute original sample drama written for this test, with three volunteer/fixture voices and self-created sound effects. Do not use a modern novel or a BBC recording as the shipped sample.

Create three ordinary website accounts. Each sees a normal name/profile screen and no wallet prompt. A creator publishes a script/root at 1,500 bps (15%). Two performers make competing children of that exact root: one asks 5,000 bps; another 2,000 bps. Both remain distinct branches. The smaller-claim branch has 170,000,000,000 effective units, 680,000,000,000 remaining, and its own as-is payout of 170/320 = 53.125%. The root's effective units remain 150,000,000,000.

Add a sound-design node at 1,000 bps on the smaller-claim branch: 68,000,000,000 effective, residual 612,000,000,000 and issued 388,000,000,000. Add a composer at 2,500 bps: effective 153,000,000,000, residual 459,000,000,000 and issued 541,000,000,000. Payouts at this fourth node are 150/541, 170/541, 68/541 and 153/541. Payouts at the prior node remain 150/388, 170/388 and 68/388.

Publish both versions using different `release_id` values. Browse by genre, open each cast profile, bookmark one version, start playback, navigate away, continue playback, seek, set a sleep timer, reload and resume. Check mobile keyboard navigation and iOS interruption/recovery manually.

Record a simulated $10.00 **distributable** receipt for the third-node version and another for the fourth. Allocate integer cents with the reference largest-remainder rule, conserve every cent, and demonstrate that the composer receives nothing from the third-node receipt. A raw purchase price is not the same as a distributable receipt; payment tests separately prove the deductions.

Tamper with the metadata name or claim, switch the program/network, substitute a same-role sibling track, replay the publish click and deliver duplicate/out-of-order payment webhooks. None may forge a valid agreement, change an existing release, duplicate a claim or double-pay.

Export a branch, public metadata, detached signatures and available artifact files. Disable the Morpheus database and host. The Tessera verifier must reconstruct the tree and exact payouts from the bundle, verify bytes/signatures offline, and distinguish that from live chain-finality verification through an independent RPC. Unknown/missing terms yield an incomplete verification report rather than a green badge.

If the test uses devnet, show **test network; resettable; not permanent evidence**. No demo should display “paid” when money was only calculated or “ownership verified” when only bytes/signatures were verified.
