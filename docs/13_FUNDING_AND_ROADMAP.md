# Funding demonstration and staged roadmap

## Minimum-funding proof

Complete L0 and L1 from [budget](../shared/LAUNCH_BUDGET.md): deterministic economics, devnet state, embedded sign, independent export, Morpheus collaboration/player and a generic second example. Use provider subdomains and rights-cleared original demo content. No token, token sale, speculative revenue numbers or compulsory expensive mainnet launch before showing the product.

A useful incubator demo is five minutes: normal login; seed 15%; expensive versus economical voice branch; complete the economical branch; play two versions; show exact payouts; turn Morpheus off; inspect the exported record with Tessera. Disclose that devnet is resettable and payments simulated. Add a measured cost card from real binary/account sizes rather than live-spending the founder's last dollars for theatrical blockchain transactions.

## Funding packet

Prepare a one-page product thesis, short demonstration recording, architecture diagram, verified cost table, risk register, versioned roadmap, actual test results, founder/team facts supplied by the founder, intended open-source terms, and a specific use of funds. Applications to the named incubator require its actual rules; none was supplied. Solana Foundation publicly offers milestone-based funding paths [S51], but acceptance is not assumed.

Ask amounts should derive from measured mainnet deployment/record capital + narrowly scoped independent review + essential paid tiers and operational reserve. Obtain quotes for review rather than setting it to zero. A free-tier demo can make the funding conversation possible without pretending production has no legal/security cost.

## Roadmap, all effort considered

V0.1: tree math, bounded program, basic identities, signed intent, independent verification, local/devnet explorer, Morpheus adapter.

V0.2: harden privacy/key recovery, managed embedded signing, metadata mirroring, exact program-cost work, reviewed extension policy, capped mainnet pilot and documented independent review.

V0.3: production operational tooling, reproducible immutable program release, more app SDKs, schema/standards exports, contributor-signed supplemental statements and controlled ecosystem onboarding.

Later research: transfers of existing effective interests; negotiated multi-parent economic merges; beneficiary key updates with explicit consent; organizational/multisig identities; revocation/dispute attestations; compression/batched anchoring with independent proofs; optional payout routing contracts. Each adds threat/legal/cost surface and receives its own spec before code.

Do not defer high-effort but necessary work simply because agents prefer scaffolding. Conversely, do not introduce generalized merges or token custody in the initial program and consume all effort before anyone can produce/listen to a drama. Finish the smallest complete, truthful loop, then extend through explicit gates.
